# PRIPRE

价格区间触达概率研究项目。以当前成交价为中心，将价格区间与未来时间窗组成概率矩阵，估计窗口内至少一次成交触达的概率，并通过历史实际频率检验校准效果。完整需求见 [TASK.md](TASK.md)。

## 当前功能

- 配置化 BTC/Binance 接入；品种与来源通过独立接口注册。
- 有预算上限的历史数据采集、分钟归档校验、成交级精确标签和压缩回放数据。
- 历史频率与路径基准、波动条件模型、独立单调校准及三段滚动回测。
- 每秒更新的完整概率热力图，最多 50 个客户端共享计算结果。
- 可靠性曲线、四模型比较、日期联动、冻结预测复盘和市场阶段研究面板。
- 数据中断、过期、预热、超出训练分布和计算超时的明确状态。
- uv/pnpm 锁定依赖、全量质量检查和 Docker Compose 部署。

行情采集必须显式启用。本地尚无至少 10 个日期的成交样本时，不生成有效概率；报告覆盖与实际验证结果以研究报告为准。健康接口只表示 API 可响应。

## 开发环境

需要 Python 3.12、uv、Node.js 24、pnpm 11.24.0、全局 pre-commit、Docker Compose。依赖以锁文件为准。

本项目在隔离 worktree 开发，完整分支约束见 [AGENTS.md](AGENTS.md)。主目录保留 `dev` 基线，验收代码位于隔离 worktree 的 `idle` 分支。


```bash

```

## 阶段 1：事件与扩展接口

`config/config.toml` 提供 BTC/Binance、价格网格、历史范围、下载预算及最多 50 个客户端的默认配置。Python 调用 `load_config(path)` 加载并校验，未知键和无效组合会报错。

品种通过 `Instrument` 描述，来源通过 `MarketSource` 接口与 `SourceRegistry` 注册；新适配器无需修改网格与标签模块。报价源必须显式声明能力，不能替代成交证据。

`touch_labels` 使用冻结网格和真实成交判定；完整但无成交记为未触达，缺失数据下未观察到的事件记为未知，已观察到的触达仍可确认。

## 阶段 2：历史与实时数据

Binance 适配器支持聚合成交历史分页及 WebSocket 实时成交。历史下载是显式操作，测试和普通服务启动不会自动下载历史数据：

```bash
uv run --locked python -m pripre.cli collect --config config/config.toml
uv run --locked python -m pripre.cli inspect --config config/config.toml
```

采集范围为 2026-01-01 至执行日（UTC）：完整月份下载分钟归档并核对官方 SHA-256，未完成月份按日采集，当天只保存已关闭分钟；每日按预先固定的轮换时段采集 420 秒聚合成交样本。聚合成交保留成交价格和时间，可生成触达标签；分钟数据只用于全范围行情状态分析。

数据按品种/来源分目录压缩保存为 NPZ，不需要额外中间件。成交价格以最小价格单位的整数保存，时间保留微秒，读取禁止 pickle。下载请求和字节使用累计预算，重复执行复用已完成文件；调整采样规则应使用新目录。清单记录成功样本、缺口、错误与下载用量。预算耗尽或数据源错误时退出并保留已完成数据，不自动放宽预算或声称完整覆盖。

## 阶段 3：基准研究与回测

```bash
uv run --locked python -m pripre.cli backtest --config config/config.toml
```

至少需要 10 个不同日期的成交样本。每个样本使用过去 60 秒计算状态，之后默认每 60 秒生成预测起点（可配置为每秒），保留完整未来观测窗口。基准模型抽取训练期真实成交路径，将相对价格变化映射到当前价格，按实际模拟成交判断触达，不填补跳空。

使用按时间扩展的滚动验证：前 10 个样本日期预热，之后每 30 个样本日期作为一段测试；每折内部再分训练与校准，只允许使用预测时刻之前已经结束的路径。输出 `data/research/report.json`，包含可靠性曲线、Brier、零概率对照、价格距离/时间窗分组、每日得分、按日重采样区间、计算延迟和全范围分钟行情上下文。数据不足或覆盖不全会体现在报告中；历史回放暂未模拟网络延迟。

## 阶段 4：条件路径模型与校准

主模型从训练期路径中选择过去 60 秒波动水平接近的路径，保留实际成交顺序、跳跃和窗口内重复访问。每折将历史可用日期再按 80%/20% 分为训练和校准，测试日期独立向后滚动；四种模型使用相同训练日期比较：分状态历史频率、无条件路径基准、条件原始概率、条件校准概率。

校准使用带先验收缩的分箱单调回归，只在独立校准集上拟合。报告同时保留四种模型的分数、低/中/高波动分组和超出训练分布的次数，不预设主模型或校准必然更好。超过训练最大波动三倍的状态标为超出分布；回测仍报告该阶段误差，实时展示暂停有效矩阵。

实时引擎与回测调用同一个估计器。引擎从本地已完成样本训练，前 80% 日期提供路径，后 20% 日期校准；默认 512 条抽样路径、固定随机种子。新增数据后重建引擎，模型不会自行联网下载。

## 实时展示与接口

先执行 `collect` 和 `backtest`，再以 `PRIPRE_LIVE_ENABLED=true` 启动 API。实时流需要 60 秒连续成交预热；断流或序号缺口后重新预热。默认配置下每秒生成 21 × 35 矩阵，50 个 WebSocket 订阅共享一个计算循环。每个客户端只保留最新帧，慢客户端不会积压队列。

- `/api/config`：当前有效配置。
- `/api/matrix`：当前快照；异常状态下 `probabilities` 为 `null`。
- `/api/stream`：每秒推送快照，超过 50 个连接时关闭新增连接。
- `/api/research`：最近一次回测报告；尚未生成时返回 404。

前端在停止接收推送 3.5 秒后清除矩阵并提示过期。研究页面可切换四种评估模型，按日期同步查看校准、模型比较、误差分组和行情，并复盘冻结的历史概率与实际触达标签；筛选不会重新训练模型。

每次更新的时间、参数和数据状态均压缩写入；有效预测同时保存参考价、固定网格、模型和概率。日志位置为 `data/live/predictions.sqlite`，最多保留最近 3600 条，避免无界增长。这是本地审计记录，不代表已完成这些预测的未来实盘校准。

## 全周期验收与追溯

滚动测试覆盖初始 10 个样本日之后的全部可用日期，不只评估后半段行情；预热日期在报告中单列。研究范围与成交采样范围分别统计，配置日期过滤对回测和行情上下文同时生效。重复分钟分区只合并完全一致的记录，冲突记录直接报错。

有效预测快照及审计记录包含模型/数据指纹、训练与校准截止时间和随机种子；无效状态记录时间和当时参数。模型拒绝使用预测起点之后的训练路径或校准数据。数据、配置或样本改变后应重新执行回测并重启实时引擎，不能复用旧报告作为新模型验收证据。

实时连接前采集三次来源服务器时间，选择最低往返延迟样本（拒绝超过 2 秒的样本）校准 UTC 锚点，此后按原始单调时钟推进预测时间，避免宿主机校时跳变影响新鲜度和每秒更新。断线重连时重新校准；来源校时不可用时保持断开状态，不把无法确认时间的行情标为有效。浏览器使用单调时间检测延迟和缓冲旧帧。

本次完整数据范围、方法、四模型分数、局限和实际验收证据见 [RESEARCH.md](RESEARCH.md)。

正式实例入口为 <http://127.0.0.1:8080>，当前已按用户要求暂停。显式启动后可访问实时矩阵和研究报告。Compose 项目名为 `pripre`，管理命令见部署说明。

### 研究审计与预测留档

回测报告包含 `origin_audit`，区分候选预测起点、有效起点与因数据覆盖不完整、缺少参考成交而排除的起点；未知窗口不能计为未触达。损坏或身份不匹配的数据直接报错，不静默排除。

`[research].origin_stride_seconds` 默认 60，可配置为 1 进行每秒历史回放；这会增加计算量，不改变每个窗口内的成交触达定义。实时 SQLite 日志保留最近 3600 个更新，包括断流、预热等无有效概率状态和当时参数；不是永久档案。

### 冻结回测与参数研究

`backtest` 现在同时写入按运行 ID 隔离的 `data/research/runs/<run_id>/replay.npz` 与报告，保存所有测试起点的冻结网格、模型概率、真实标签、波动状态和异常标记。报告生成完成后才更新当前报告；旧运行保留供复核。备份时应将整个 `data/research/` 一起备份，不能仅复制报告文件。

- `GET /api/research?start=2026-02-01&end=2026-02-28`：仅重算已保存样本外预测的指标，不重训；分组包含样本量、日期数、未知比例及按日分块 95% 区间。日期没有样本时返回空指标，不沿用全周期结果。
- `GET /api/replay?start=...&end=...&offset=0&limit=100`：分页列出历史预测；`GET /api/replay/<timestamp_us>?model=conditional-calibrated`：取得固定网格、概率及真实触达标签。
- `uv run --locked python -m pripre.cli experiments --config config/config.toml`：在前 60% 日期训练、中间 20% 日期抽取最多 20 个按时间均匀间隔的开发起点，比较路径数、种子、候选比例、稀疏回退、价格映射、路径长度及路径库采样粒度。最后 20% 日期不参与该实验，不据此自动切换实时模型。
- `GET /api/experiments`：读取开发实验结果。不同预测长度对应不同目标，不能直接按 Brier 排名。

新增历史频率基准使用训练期波动四分位阈值划分三种状态，状态少于 16 个起点时合并回全体训练样本；没有标签证据的格子报错。原无条件路径基准继续保留。

趋势/震荡与特殊事件属于事后研究标注，不能用于当时的预测特征。趋势规则为日内方向效率（绝对首尾对数收益 / 分钟绝对对数收益之和）乘分钟数平方根至少为 1；特殊事件为全范围日内绝对收益前 5%。报告列出日期、成交样本覆盖、分组误差及区间；极端日期的 7 分钟样本不等于事件全过程。

### 面板使用

实时矩阵和历史预测共用连续红色渐变，浅红表示低概率、深红表示高概率，不再将概率合并为少数档位。固定使用 `色深位置 = sqrt(概率)`，为低概率区间提供更多颜色变化；原始概率保持不变，跨帧使用相同映射。图例按真实百分比标注 0%、1%、5%、10%、25%、50%、75%、100%，悬停显示原始概率的百分比、价格区间与未来窗口。实际标签也用浅红/深红区分未触达/已触达，空白仍表示未知。

配色与映射参考 [Matplotlib 色阶说明](https://matplotlib.org/stable/users/explain/colors/colormaps.html)及 [ECharts visualMap](https://echarts.apache.org/handbook/en/concepts/visual-map/)。

在研究页选择 UTC 起止日期并点击“应用范围”，可靠性、模型比较、分组误差与行情同步更新；点击“全范围”恢复完整报告。没有样本的日期显示空指标。全量数据条数、回测耗时与开发实验单独标注，不作为筛选后的统计。

“历史预测复盘”按每页 100 个起点浏览，选择时刻和评估模型后并排查看固定网格的预测概率与真实触达标签；空白标签表示未知。复盘仅使用已保存样本外结果，不移动历史边界、不切换实时模型。分组详情提供样本量、日期数和区间；全量诊断区可查看事件日期、排除审计、开发期参数与多种子实验。旧报告没有运行 ID 时，需要重新执行 backtest 生成复盘证据。

### 源时钟与预测时效

Linux 下使用 `CLOCK_MONOTONIC_RAW` 外推 Binance UTC，并用相同的原始时钟测量校时 RTT、计算耗时及更新周期，避免宿主机 NTP 调速使行情被误判为过期。其他平台回退到普通单调时钟，并继续执行复校与失效保护。

`[runtime].clock_sync_seconds` 默认为 30，`clock_max_age_seconds` 默认为 90，后者必须大于前者。每轮最多三次公共时间请求，底层 HTTP 超时为 2 秒、每次异步等待最多 3 秒，避免已取消的阻塞读取长期占用校时请求锁；选择 RTT 不超过 2 秒的最低延迟样本。短暂复校失败保留尚未过期的校准；超过有效期暂停概率、清空特征缓冲，恢复后重新预热。超过 500 ms 的时间修正也会重新预热，并丢弃修正前尚未完成或排队的预测。

快照包含 `elapsed_clock`、`clock_sync_age_ms`、`clock_syncs`、`clock_sync_failures`、`clock_adjustment_us`、`clock_epoch` 供诊断。WebSocket 使用 `stream_id`、`frame_sequence`、`frame_elapsed_us` 及服务端计算的 `frame_age_ms` 判断推送进度与排队时长；前端不再把 UTC 与浏览器时钟长期固定对齐。重复帧不刷新时效，断推送、突发传输延迟或排队超过约 3.5 秒仍会清除矩阵并重新订阅。渐进网络延迟与首次连接前的网络缓存无法仅靠两端独立时钟精确测量，此检查不是端到端绝对延迟证明。

### 数据源代理

使用专用环境变量 `PRIPRE_SOURCE_PROXY`，同时控制历史归档、REST 成交、源时间校准和实时 WebSocket。支持 HTTP 代理（包括带账号密码的 HTTP CONNECT）；HTTPS/WSS 目标继续执行原有 TLS 证书校验。SOCKS 和到代理本身的 HTTPS 协议暂不接受，错误配置会明确报错。

```bash
# 在宿主机运行 CLI：填写宿主机可访问的代理地址
PRIPRE_SOURCE_PROXY=http://127.0.0.1:7077 uv run --locked python -m pripre.cli source-check --config config/config.toml
PRIPRE_SOURCE_PROXY=http://127.0.0.1:7077 uv run --locked python -m pripre.cli collect --config config/config.toml
```

留空表示显式直连。数据源客户端不再自动继承 `HTTP_PROXY`、`HTTPS_PROXY`、`ALL_PROXY` 或 `NO_PROXY`，避免 HTTP 与 WebSocket 走不同出口；指定代理失败时不会偷偷回退直连。CLI 不自动读取 `.env`，需导出变量或使用上面的命令前缀。

`source-check` 是手动触发的连通性检查：最多一次 HTTP 时间请求（64 KiB 预算）及一次 WebSocket 订阅，只读取一条成交后关闭，失败退出码为 1。不下载历史数据、不生成预测，也不在服务启动时自动执行。输出区分 HTTP 和 WebSocket，并移除代理地址中的账号密码；`/api/config` 仅返回 `network.source_proxy_enabled` 标志。代理配置不写入研究报告或模型指纹。

Docker 使用的地址与宿主机 CLI 不同：Docker Desktop 通常填写 `http://host.docker.internal:7077`；原生 Linux 的宿主机路由见 COMPOSE.md。容器内的 `127.0.0.1` 指容器自身。

数据源返回 418/429 时，HTTP 客户端会遵守数值形式的 `Retry-After`（缺失或无效时等待 60 秒），冷却期间不再发送 HTTP 请求。`source-check` 返回状态码与等待秒数；切换代理出口后重新运行检查，运行服务需重建或重启后端以清除原出口的冷却状态。
