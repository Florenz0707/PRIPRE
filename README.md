# PRIPRE

价格区间触达概率研究项目。以当前成交价为中心，将价格区间与未来时间窗组成概率矩阵，估计窗口内至少一次成交触达的概率，并通过历史实际频率检验校准效果。完整需求见 [TASK.md](TASK.md)。

## 当前功能

- 配置化 BTC/Binance 接入；品种与来源通过独立接口注册。
- 有预算上限的历史数据采集、分钟归档校验、成交级精确标签和压缩回放数据。
- 历史路径基准、波动条件模型、独立单调校准及三段滚动回测。
- 每秒更新的完整概率热力图，最多 50 个客户端共享计算结果。
- 可靠性曲线、三模型比较、波动阶段/价格距离/时间窗误差及全周期行情面板。
- 数据中断、过期、预热、超出训练分布和计算超时的明确状态。
- uv/pnpm 锁定依赖、全量质量检查和 Docker Compose 部署。

行情采集必须显式启用。本地尚无至少 10 个日期的成交样本时，不生成有效概率；报告覆盖与实际验证结果以研究报告为准。健康接口只表示 API 可响应。

## 开发环境

需要 Python 3.12、uv、Node.js 24、pnpm 11.24.0、全局 pre-commit、Docker Compose。依赖以锁文件为准。

本项目在隔离 worktree 开发，完整分支约束见 [AGENTS.md](AGENTS.md)。主目录保留 `dev` 基线，验收代码位于隔离 worktree 的 `idle` 分支。

在隔离 worktree 根目录执行：

```bash
uv sync --locked
pnpm install --frozen-lockfile
pre-commit install
```

分别打开两个终端：

```bash
# 后端：http://127.0.0.1:8000，接口文档：http://127.0.0.1:8000/docs
# 先完成下方 collect；显式启用真实行情
PRIPRE_CONFIG=config/default.toml PRIPRE_LIVE_ENABLED=true uv run --locked uvicorn pripre.api:app --reload --host 127.0.0.1 --port 8000
```

```bash
# 前端：http://127.0.0.1:5173；/api 请求由 Vite 代理到后端
pnpm dev
```

## 质量检查

```bash
# 新文件必须先暂存，确保 pre-commit 纳入检查
uv run --locked python scripts/check.py
```

统一入口运行锁文件检查、全部后端/前端测试、前端生产构建、`pre-commit run --all-files` 和 Compose 配置校验。配置校验不需要 Docker daemon，但容器构建和运行需要。

单独运行测试和质量工具：

```bash
uv run --locked pytest
pnpm test
pnpm build
pre-commit run --all-files
```

hooks 使用 uv/pnpm 锁定的本地工具，覆盖 Ruff、mypy、ESLint、vue-tsc、Prettier、TOML 格式化、配置语法、冲突标记和私钥检查。格式化造成修改后需重新暂存并重跑全量检查。

## 目录

```text
backend/src/pripre/
  api.py           HTTP 应用边界
  data/            成交接入、预算、存储与质量检查
  features/        市场状态与全周期行情上下文
  models/          历史路径、条件模型与校准
  backtesting/     回放、精确标签、滚动回测与指标
backend/tests/     后端测试

scripts/check.py   统一质量检查入口
```

当前计算使用 NumPy，图表使用 ECharts，数据保存为 NPZ；预测日志使用 Python 标准库 SQLite。无需 PostgreSQL、Redis 或其他额外服务。

## 阶段 1：事件与扩展接口

`config/default.toml` 提供 BTC/Binance、价格网格、历史范围、下载预算及最多 50 个客户端的默认配置。Python 调用 `load_config(path)` 加载并校验，未知键和无效组合会报错。

品种通过 `Instrument` 描述，来源通过 `MarketSource` 接口与 `SourceRegistry` 注册；新适配器无需修改网格与标签模块。报价源必须显式声明能力，不能替代成交证据。

`touch_labels` 使用冻结网格和真实成交判定；完整但无成交记为未触达，缺失数据下未观察到的事件记为未知，已观察到的触达仍可确认。

## 阶段 2：历史与实时数据

Binance 适配器支持聚合成交历史分页及 WebSocket 实时成交。历史下载是显式操作，测试和普通服务启动不会自动下载历史数据：

```bash
uv run --locked python -m pripre.cli collect --config config/default.toml
uv run --locked python -m pripre.cli inspect --config config/default.toml
```

采集范围为 2026-01-01 至执行日（UTC）：完整月份下载分钟归档并核对官方 SHA-256，未完成月份按日采集，当天只保存已关闭分钟；每日按预先固定的轮换时段采集 420 秒聚合成交样本。聚合成交保留成交价格和时间，可生成触达标签；分钟数据只用于全范围行情状态分析。

数据按品种/来源分目录压缩保存为 NPZ，不需要额外中间件。成交价格以最小价格单位的整数保存，时间保留微秒，读取禁止 pickle。下载请求和字节使用累计预算，重复执行复用已完成文件；调整采样规则应使用新目录。清单记录成功样本、缺口、错误与下载用量。预算耗尽或数据源错误时退出并保留已完成数据，不自动放宽预算或声称完整覆盖。

## 阶段 3：基准研究与回测

```bash
uv run --locked python -m pripre.cli backtest --config config/default.toml
```

至少需要 10 个不同日期的成交样本。每个样本使用过去 60 秒计算状态，之后每 60 秒生成预测起点，保留完整未来观测窗口。基准模型抽取训练期真实成交路径，将相对价格变化映射到当前价格，按实际模拟成交判断触达，不填补跳空。

使用按时间扩展的滚动验证：前 10 个样本日期预热，之后每 30 个样本日期作为一段测试；每折内部再分训练与校准，只允许使用预测时刻之前已经结束的路径。输出 `data/research/report.json`，包含可靠性曲线、Brier、零概率对照、价格距离/时间窗分组、每日得分、按日重采样区间、计算延迟和全范围分钟行情上下文。数据不足或覆盖不全会体现在报告中；历史回放暂未模拟网络延迟。

## 阶段 4：条件路径模型与校准

主模型从训练期路径中选择过去 60 秒波动水平接近的路径，保留实际成交顺序、跳跃和窗口内重复访问。每折将历史可用日期再按 80%/20% 分为训练和校准，测试日期独立向后滚动；三种模型使用相同训练日期比较：无条件基准、条件原始概率、条件校准概率。

校准使用带先验收缩的分箱单调回归，只在独立校准集上拟合。报告同时保留三种模型的分数、低/中/高波动分组和超出训练分布的次数，不预设主模型或校准必然更好。超过训练最大波动三倍的状态标为超出分布；回测仍报告该阶段误差，实时展示暂停有效矩阵。

实时引擎与回测调用同一个估计器。引擎从本地已完成样本训练，前 80% 日期提供路径，后 20% 日期校准；默认 512 条抽样路径、固定随机种子。新增数据后重建引擎，模型不会自行联网下载。

## 实时展示与接口

先执行 `collect` 和 `backtest`，再以 `PRIPRE_LIVE_ENABLED=true` 启动 API。实时流需要 60 秒连续成交预热；断流或序号缺口后重新预热。默认配置下每秒生成 21 × 35 矩阵，50 个 WebSocket 订阅共享一个计算循环。每个客户端只保留最新帧，慢客户端不会积压队列。

- `/api/config`：当前有效配置。
- `/api/matrix`：当前快照；异常状态下 `probabilities` 为 `null`。
- `/api/stream`：每秒推送快照，超过 50 个连接时关闭新增连接。
- `/api/research`：最近一次回测报告；尚未生成时返回 404。

前端在停止接收推送 3.5 秒后清除矩阵并提示过期。研究页面可切换三种模型，筛选行情图的日期，并查看校准、误差分组与滚动区间。行情日期筛选不改变上方完整测试集指标。

有效预测的时间、参考价、固定网格、模型、概率和数据状态压缩写入 `data/live/predictions.sqlite`，最多保留最近 3600 条，避免无界增长。这是本地审计记录，不代表已完成这些预测的未来实盘校准。

## 全周期验收与追溯

滚动测试覆盖初始 10 个样本日之后的全部可用日期，不只评估后半段行情；预热日期在报告中单列。研究范围与成交采样范围分别统计，配置日期过滤对回测和行情上下文同时生效。重复分钟分区只合并完全一致的记录，冲突记录直接报错。

每个实时快照及审计记录包含算法/数据指纹、训练与校准截止时间和随机种子。模型拒绝使用预测起点之后的训练路径或校准数据。数据、配置或样本改变后应重新执行回测并重启实时引擎，不能复用旧报告作为新模型验收证据。

实时连接前采集三次来源服务器时间，选择最低往返延迟样本（拒绝超过 2 秒的样本）校准 UTC 锚点，此后按单调时钟推进预测时间，避免宿主机校时跳变影响新鲜度和每秒更新。断线重连时重新校准；来源校时不可用时保持断开状态，不把无法确认时间的行情标为有效。浏览器使用单调时间检测延迟和缓冲旧帧。

本次完整数据范围、方法、三模型分数、局限和实际验收证据见 [RESEARCH.md](RESEARCH.md)。

本次验收后保留的本地实例：<http://127.0.0.1:8080>，包含实时矩阵和完整研究报告。Compose 项目名为 `pripre`，管理命令见部署说明。

### 研究审计与预测留档

回测报告包含 `origin_audit`，区分候选预测起点、有效起点与因数据覆盖不完整、缺少参考成交而排除的起点；未知窗口不能计为未触达。损坏或身份不匹配的数据直接报错，不静默排除。

`[research].origin_stride_seconds` 默认 60，可配置为 1 进行每秒历史回放；这会增加计算量，不改变每个窗口内的成交触达定义。实时 SQLite 日志保留最近 3600 个更新，包括断流、预热等无有效概率状态和当时参数；不是永久档案。
